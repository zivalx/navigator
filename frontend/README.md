# Navigator Frontend

React SPA for Navigator — portfolio tracking, watchlists, market data, and market indicators. Talks to the FastAPI backend in `../backend` over `/api`.

## Stack

- **React 18** + **TypeScript**, built with **Vite** (`@vitejs/plugin-react-swc`)
- **React Router** (`react-router-dom`) for client-side routing
- **TanStack React Query** for server-state (currently only `QueryClientProvider` is wired up in `App.tsx`; most data fetching today goes through the context layer, see below)
- **shadcn/ui** components on top of **Radix UI** primitives, styled with **Tailwind CSS**
- **next-themes**-style light/dark theming via a custom `ThemeContext` (see Theming)
- **recharts** for charts, **sonner** for toasts, **zod** + **react-hook-form** for forms

## Prerequisites

- Node.js 18+
- The backend running and reachable on `http://localhost:7000` (see `../backend/README.md` or the repo root `README.md`). The dev server proxies `/api` there — the frontend will start without it, but data fetches will fail.

## Install, run, build

```bash
npm install       # install dependencies (package-lock.json is the source of lock; a bun.lockb also exists from the project's Lovable origin — stick to npm)
npm run dev       # start Vite dev server, http://localhost:7070
npm run build     # production build to dist/
npm run build:dev # build in development mode (unminified, useful for debugging a build-only issue)
npm run preview   # serve the built dist/ locally
npm run lint      # eslint over the whole project
```

There is no dedicated `typecheck` script. Run the TypeScript compiler directly when you want a standalone type check:

```bash
npx tsc -b --noEmit
```

Note: `tsconfig.app.json` has `strict: false`, `noImplicitAny: false`, and `strictNullChecks: false`, so this is a fairly loose type check by default — don't rely on it to catch everything.

## How API calls work

`vite.config.ts` runs the dev server on port **7070** and proxies any request to `/api/*` to `http://localhost:7000` (the backend):

```ts
server: {
  port: 7070,
  proxy: {
    "/api": { target: "http://localhost:7000", changeOrigin: true },
  },
},
```

All API calls go through the single client in `src/lib/api.ts`. It's a thin `fetch` wrapper (`request<T>()`) that prefixes every path with `/api`, sets JSON headers, and throws on non-OK responses. The `api` object exposes one method per backend endpoint (assets, portfolio holdings, watchlists, markets/quotes, movers, indicators). There's no separate API client per feature — add new backend calls as new methods on this object.

In production, the built static files are served by nginx (see repo-root `nginx/`), which is expected to proxy `/api` the same way.

## Directory structure

```
src/
  components/
    ui/          shadcn/ui primitives (button, dialog, table, etc.) — generated by shadcn CLI, avoid hand-editing structure
    layout/       AppLayout — page shell (nav/sidebar) wrapping every route
    dashboard/     components specific to the Index (home/dashboard) page
    portfolio/     holdings table, add-holding dialog, portfolio-specific widgets
    watchlist/     WatchlistTable and related watchlist UI
    markets/       market cards / movers UI for the Markets page
    heatmap/       Heatmap page components
    settings/      Settings page components
    common/        shared, cross-page components (e.g. GlobalSearch)
  contexts/       app-wide React Context providers (state management, see below)
  pages/          one file per route, thin — compose AppLayout + feature components
  lib/            api client, shared types, mock data, utils
  hooks/          shared hooks (use-toast, use-mobile, useIndicatorPrefs)
  App.tsx         providers + router + route table
  main.tsx        React root, mounts <App />
  index.css       Tailwind base + CSS variables for theming
```

## State management

There's no Redux/Zustand — app state lives in three React Contexts, all mounted in `App.tsx` (order matters: `ThemeProvider` > `PortfolioProvider` > `MarketCardsProvider`):

- **`ThemeContext`** (`src/contexts/ThemeContext.tsx`) — `theme: 'light' | 'dark'`, persisted to `localStorage`, applied by toggling the `light`/`dark` class on `<html>`. Exposes `useTheme()`.
- **`PortfolioContext`** (`src/contexts/PortfolioContext.tsx`) — the big one: assets, holdings, watchlists, watchlist items, alerts, computed portfolio summary/top movers/grouped holdings, and all the CRUD actions (add/remove/update holding, watchlist management, import, search). Fetches from `api` on mount and polls every 60s. Exposes `usePortfolio()`.
- **`MarketCardsContext`** (`src/contexts/MarketCardsContext.tsx`) — the customizable market-ticker cards on the dashboard: card layout persisted to `localStorage`, live prices polled from `api.getQuotes` every 60s, plus edit-mode/reorder/move actions. Exposes `useMarketCards()`.

Local/ephemeral UI state (dialogs open, form fields, etc.) stays in component `useState` — only cross-page or persisted state belongs in a context.

## Adding a new page

1. Create `src/pages/YourPage.tsx`. Keep it thin: wrap content in `<AppLayout>` and delegate real UI to components.
2. Put page-specific components in a new or existing `src/components/<area>/` folder (e.g. `src/components/yourpage/YourWidget.tsx`).
3. Register the route in `src/App.tsx`: add `<Route path="/your-page" element={<YourPage />} />` inside `<Routes>`, above the catch-all `*` → `NotFound` route.
4. Add a nav entry in `src/components/layout/AppLayout.tsx` if the page should be reachable from the main navigation.
5. If the page needs shared/cross-page state, extend an existing context or add a new provider in `App.tsx`; if it just needs data, add a method to `src/lib/api.ts`.

## Theming

Light/dark mode is handled by the custom `ThemeContext`, not `next-themes` directly (despite `next-themes` being a dependency — it's unused by the current theme implementation; the shadcn `sonner`/`toast` components reference it but the app's own toggle goes through `ThemeContext`). Theme state persists to `localStorage` under the `theme` key and falls back to the OS preference (`prefers-color-scheme`) on first load. Tailwind's `dark:` variant classes and the CSS variables in `index.css` drive the actual visual styling; toggling is done via `useTheme().toggleTheme()`.

## Types

Shared domain types (`Asset`, `HoldingLot`, `Watchlist`, `PortfolioSummary`, `MarketIndicator`, etc.) live in `src/lib/types.ts`. Feature-local type modules sit alongside it: `src/lib/marketCardTypes.ts` (dashboard market cards) and `src/lib/indicatorTypes.ts` (market indicators — see the indicator components under active development for how these are consumed). Prefer adding to `types.ts` for anything shared across more than one page/context; keep single-feature types in their own `lib/*Types.ts` file.

## Path alias

`@/*` maps to `src/*` (configured in both `vite.config.ts` and `tsconfig.app.json`) — use `@/lib/...`, `@/components/...`, `@/contexts/...` instead of relative `../../` imports.
